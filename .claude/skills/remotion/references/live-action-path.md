# 从功能动画走到「宣传级实拍片」的技术路径

> 目标：真人、真车、真宠物，蔚来宣传片的质感。
> 这份文档回答三件事：**能不能做、怎么做、我们现在做的东西在其中是什么位置。**

## 一、先把边界说清楚

**本环境不能生成实拍画面。** 这不是保守估计，是硬约束：

- 没有可用的视频生成模型（Sora / Veo / 可灵 / 即梦 / Runway 一类），出网也受限
- Remotion 是**渲染你画的东西**，不是合成照片级画面；它做不出实拍质感
- 没有 3D 渲染管线；即便有，一台照片级的 ES9 需要官方 CAD/DMU、材质库、HDRI 与灯光师，
  那是整个工作室的活，不是一个脚本能替代的

**更重要的是：即使有生成模型，也不该用它做这件事。** 宣传级要求车型细节准确
（大饼轮毂 9 个孔、灯带走向）、尺寸真实（装载口 787mm）、动作合规（尾门开启角度）。
生成模型对这些**没有约束能力**——每一帧的轮毂孔数都可能不一样。而未上市功能一旦用生成画面，
会产出「看起来像实拍但不是真的」的素材，法务风险远高于一眼可辨的概念插画。

**所以：宣传级实拍片是一个拍摄工程，不是渲染工程。** 它的成本大头在样车、场地、灯光、
动物驯导、保险、法务审批，这些都不是技术问题。

## 二、三条路径

### 路径 A：实拍 +「动画当分镜与技术底稿」（最现实，投入产出比最高）

拍摄前最缺的三样东西，我们的决策卡里**已经有了**：

| 拍摄需要 | 决策卡里对应 |
|---|---|
| 每个镜头为什么存在 | `chapters[].claim` |
| 镜头必须拍到什么可量化事实 | `acceptance[]` 里带数字的条目 |
| 构图与机位参数 | `*-geo.ts` 的实测标定（787mm 装载口高、23° 坡度、700mm 可及半径） |
| 开拍前必须归零的事 | `conceptualItems[]` |

最后一条是**实拍与插画的分水岭**：概念件可以画，但拍不出来。
斜坡架动画现在有 8 项未定义、宠物包有 10 项——这两个功能**今天不具备开拍条件**，
因为那些东西还不存在。这不是坏消息，这是把"什么时候能拍"变成了一张可执行的清单。

用 `scripts/make-shotlist.mjs` 把决策卡转成分镜表：

```bash
node scripts/make-shotlist.mjs ramp-manifest.json > ramp-shotlist.md
```

产出包含：开拍前必须归零的项（含归零方式）、逐章镜头表（景别/机位/内容/时长）、
必须拍到的可量化事实（验收清单）、拍摄注记、合规清单。

### 路径 B：实拍空镜 + 后期动态图形叠加（中等成本，行业通行做法）

真车真人实拍，**功能中「看不见」的那部分**用后期叠加：信号链路、锁舌咬合、坡度标注、
可及范围、三级固定的指向线。这正是这类科技宣传片的标准做法——观众以为是实拍，
其实关键信息全是后期加的。

我们的动画可以直接当**叠加层的设计稿与运动曲线来源**：同一份 Remotion 组件，
把背景改成透明，导出带 alpha 的序列给剪辑用。

```bash
# PNG 序列（带 alpha，最通用）
npx remotion render <CompId> out/frame.png --image-format=png \
  --browser-executable=/opt/pw-browsers/chromium --chrome-mode=chrome-for-testing

# ProRes 4444（带 alpha，直接进 Premiere / DaVinci）
npx remotion render <CompId> out.mov --codec=prores --prores-profile=4444 --pixel-format=yuva444p10le \
  --browser-executable=/opt/pw-browsers/chromium --chrome-mode=chrome-for-testing
```

叠加层要额外满足：

- `AbsoluteFill` 的 `background` 必须去掉（透明），地面/环境色块也要去掉
- 叠加图形的**位置要跟实拍画面对齐**——拍摄时在起幅/落幅各留 1s 静止，后期才好对点
- 数字标注的字号要按最终交付分辨率给，不要按 1000×560 舞台想当然
- 安全区：叠加层不要压住车标、车牌、人脸

### 路径 C：AI 生成（现在不可行，且不该用在主体上）

见第一节。**唯一可考虑的用法是氛围空镜**（雪景、山路、天光），车辆与功能主体不能交给它。
真要用，产出必须标注为 AI 生成并单独走法务。

## 三、还有一条中间路线：把现在的动画提到「影片级」

不追求真人真车，但可以从「网页演示」提到「能放在评审会/发布会上的产品讲解片」：

- 导出 MP4，加转场、字幕条动效、音乐节拍对齐
- 把照片素材换成官方无水印高清图
- 增加片头片尾、统一的视觉节奏

这条今天就能做，成本是渲染一次 MP4。**但要注意**：MP4 一旦渲出来就不好改，
必须在 HTML 定稿、用户验收之后再渲，且只渲一次（见 SKILL.md 交付策略）。

## 四、决策卡要加的字段

```json
{
  "deliverable": ["explainer-html"],
  "liveActionReadiness": {
    "blockers": 8,
    "earliestShootWindow": "样件冻结后",
    "notes": "犬只需驯导师；空气悬架装载模式待确认，会改变坡度口径"
  }
}
```

`deliverable` 可选：`explainer-html`（默认）· `explainer-mp4` · `shot-list`（给拍摄用的分镜表）
· `overlay-plates`（给后期用的带 alpha 叠加层）。

`liveActionReadiness.blockers` 直接等于 `conceptualItems.length`——**它归零之前，
实拍这条路是走不通的**，这是这份文档最该被记住的一句话。

## 五、给需求方的一句话总结

> 想拍真人真车真宠物的宣传片，技术不是瓶颈，**需求收敛才是**。
> 现在这版动画的价值不在于它像不像实拍，而在于它把「拍之前必须定下来的每一件事」
> 都逼出来写在了纸上——斜坡架 8 条、宠物包 10 条。这些归零那天，分镜表一键就能生成。
