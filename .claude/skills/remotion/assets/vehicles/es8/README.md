## 座舱照片怎么标定（宠物包动画的做法，可复制）

选缩放 s 的判据不是「看着大小合适」：**让照片的 mm/px 换算和舞台那把尺子一致**。
photo 内宽 600px × s ≈ 舞台座舱内宽 245.5px（尺子 6.6mm/px）→ s=0.41，
于是 REACH_R(700mm) 这类几何主张在照片上直接成立，不用重标。
tx/ty 由两个锚点解出（岛台中线→PLAN.cx、前排 H 点→PLAN.yRow1），
标完跑数值断言逐项对（岛台边缘/软包段/座椅中心 ±1px）。

## 为什么手上那张俯视图不能用

`photos/es8/es8-topdown-rear-highangle.jpg` 是**从车后上方拍的**，不是正投影。

判定过程（`scripts/assert-orthographic.py`）：

```
① 长宽比      2.324  实车 2.627  偏差 -11.5%  ❌
② 轴距/车长   0.496  实车 0.593  偏差 -16.3%  ❌
```

**两条都偏是关键。** 如果只是均匀缩放（视频截帧常见），长度和轴距同比缩，
第二条**不会**偏——ES9 现用的那张就是这样，归正后 −0.1% / +0.0% 两条全过。
两条都偏说明是真透视。

放大车尾也能直接确认：整个尾门立面（贯穿式尾灯、NIO 标、牌照凹槽、后杠）都看得见。
**正投影看不到任何垂直面。**

后果是硬的：**透视图不能在平面内旋转**。泊车动画里车要转 22°，一转，
那些本不该看见的垂直面就会跟着甩，物理上不可能。拉伸校正也救不回来——
拉了只是把透视图拉变形。

所以它登记为 **reference-only**：可以用来读造型、灯语、车顶特征（激光雷达位置、
贯穿式尾灯），**不得直接贴图**。

## 补素材时要什么

一张**相机正对车顶、看不到任何垂直面**的俯视图。拿到之后跑：

```bash
python3 scripts/assert-orthographic.py <图> --len-mm 5280 --wid-mm 2010 --wb-mm 3130
```

两条判据都过再进入抠形流程。深色背景 + 深色车时脚本会拒绝自动量（这是对的，
免得给出一组看着像模像样的假数），改用 `cutout-trace.py grid` 放大读数后手工传入。

抠形与标定的完整做法照 `es9/top.ts` 和 `es9/side.ts` 的文件头，那两份里记着
逐像素实测的方法和已经踩过的坑。
