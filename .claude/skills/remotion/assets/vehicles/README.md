# 车辆资产库（按车型分目录）

```
vehicles/
  _shared/      与车型无关：配色 token、蔚来 Logo、四轮转向运动学、贴身信息卡、环境道具
  es9/          ES9：实车规格、正侧视、正俯视、轮毂          ← 素材齐全，可直接做动画
  es8/          ES8：**座舱素材齐全**（全舱俯视 + 前排正侧实拍）；车外贴图无 ← 见 es8/README.md
```

## 怎么选素材：先看需求说没说车型

**绝大多数功能演示不涉及具体车型**——讲的是全地形、泊车、对讲机这些功能本身。
这种情况**不要在车型上纠结**：

- **需求没点名车型** → 只按「**需要哪个视角**」取素材，用资产库里该视角**齐全的那一套**
  （当前是 `es9/`）。这是默认路径，不用问、不用犹豫，也不要在画面上强调车型标识。
- **需求明确点了车型**（「ES8 的…」「ET9 上…」）→ 调那个车型的目录。
  该车型素材不全就**如实说做不了、缺什么**，不要拿别的车型顶上——
  两台车三围就不同（ES9 5365×2029 / ES8 5280×2010），外形也不同，
  换个标签糊弄过去，看的人一眼认出不是自己那台车。

| 车型 | 状态 | 入口 |
|---|---|---|
| **ES9** | ✅ 齐全 | 正侧视 `<ES9SideView />` · 正俯视 `ES9_TOP` ← **未点名车型时的默认** |
| **ES8** | ✅ 座舱齐全（车外无） | 座舱俯视/前排正侧见 `es8/README.md`；车外俯视那张是透视图，判废 |

**加新车型就加一个平级目录**（`et9/`、`es6/`…），照 `es9/` 的文件名与导出结构照抄。
不要把新车型的贴图塞进 `es9/`，也不要建 `nio-vehicle/` 这种不分车型的目录——
一旦两个车型混在一起，下一个人分不清哪张图是哪台车，动画里就会出现「前后不是同一台车」。

## 调用规则（强制）

**一个视角只有一份指定素材。视角定了，图就定死了。**

| 车型 | 视角 | 唯一入口 | 说明 |
|---|---|---|---|
| ES9 | **正侧视** | `es9/SideView.tsx` → `<ES9SideView />` | 开箱即用，含遮罩/镜像/旋转轮辋/高光/投影 |
| ES9 | **正俯视** | `es9/top.ts` → `ES9_TOP` | 泊车动画那张实拍图 |
| ES9 | 轮毂（矢量） | `es9/Wheel.tsx` | **兜底**，只在拿不到可用照片时用 |

判断流程就一句话：**功能演示要用 ES9 正侧视 → 直接 `<ES9SideView />`**。
不要另找图、不要画矢量车、不要沿用别的车型的轮廓、不要「照着调一下参数」。

同一个车型在不同动画里长得不一样，团队一眼就看出是拼的，可信度直接归零。
**换视角可以，换车不行。**

## 怎么用

```bash
cp -r .claude/skills/remotion/assets/vehicles/_shared my-video/src/assets/_shared
cp -r .claude/skills/remotion/assets/vehicles/es9     my-video/src/assets/es9
```

```tsx
import {ES9SideDefs, ES9SideView} from './assets/es9/SideView';
import {sideWheelDeg} from './assets/es9/side';

<svg viewBox="0 0 1000 560">
  <defs><ES9SideDefs /></defs>
  {/* 地形 / 背景 */}
  <ES9SideView deg={sideWheelDeg(dx)} bob={bob} />
  {/* 前景道具 / 信息卡 */}
</svg>
```

**复制不要引用。** 交付过的动画要把资产复制进自己工程，否则 skill 一更新就会改变旧动画。

舞台坐标系固定 **1000 × 560**（对应 CSS 1920 × 1075）。换舞台尺寸时整组套一层 `scale`，
不要去改组件里的数字——那些数和 `side.ts` 的标定绑死。

## 改完素材要跑同步校验

资产库是「复制不要引用」的——动画工程各自持有一份拷贝。代价是**两边会各自往前走**：
在工程里改了轮廓/贴图/灯带、忘了同步回资产库，下一个功能就会从旧版起手。
这种漂移**肉眼发现不了**（base64 几万字符、轮廓几百个数字）。

```bash
python3 scripts/assert-assets-in-sync.py --project animations
```

逐项比 md5。不一致时**不要直接覆盖**——两边都可能是新的，先确认哪一版对再同步。

## 每个车型目录应该有什么

| 文件 | 内容 |
|---|---|
| `spec.ts` | 实车规格（长宽高轴距）+ mm/px 标尺换算 + 比例自检 |
| `side.ts` | 正侧视照片 + 车身轮廓 + 轮心/胎圈标定 + 舞台摆位 + 语义锚点 |
| `side-rim.ts` | 可旋转轮辋圆盘（带 alpha 的 PNG） |
| `SideView.tsx` | 正侧视开箱即用组件 |
| `top.ts` | 正俯视照片 + 轮廓 + 包围盒 + 锚点 + 大灯灯带 |
| `Wheel.tsx` | 矢量轮毂（兜底） |

## 换素材 / 改轮廓前必读

`es9/side.ts` 顶部记着这台车的轮廓是怎么测出来的，以及**五个已经踩过的坑**：
不能从别的照片平移、扫描方向要和边界走向垂直、单像素触发不要用连续 N 像素、
采样密度要跟特征尺度匹配、轮胎下缘量不出来只能按胎圈半径补。

**改之前先读那一段。** 这条轮廓是逐像素实测 + 多轮返工的结果，
凭感觉调参数只会退回到已经修好的老问题上。
