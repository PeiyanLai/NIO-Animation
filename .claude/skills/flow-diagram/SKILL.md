# flow-diagram · 交互式用户流程图生成

把一份需求/功能文档变成一张**可拖拽、可编辑、可筛选**的交互流程图。产出是单个自包含 HTML（零外部依赖，可发 Artifact、可嵌 WebView、可直接静态托管），配色遵循 NIOFlow 设计规范。

## 产出物功能清单（成品自带，无需额外开发）

- 全屏画布：铺满页面，分区虚线框**自动贴合**成员节点，画布尺寸随内容收缩/扩展
- 节点：单击＝打开编辑表单（标题/副标题/描述/用户类型/场景/依赖端/分区/样式），拖拽＝移动（连线实时跟随）
- 连线：点击可改标签、反转方向、删除；「从此节点连线」创建新边
- 工具条：场景筛选 × 用户类型筛选（双维联动淡出）、＋新增节点、导出 JSON、恢复默认、缩放（适应铺满/±/100%）、重置布局
- 所有修改自动保存到浏览器 localStorage（按 KEY 隔离）；「导出 JSON」可把某人的编辑取回并入默认数据
- 亮/暗双主题跟随系统（暗色按规范 #0a0a0a + #00D4D4）

## 工作流程

### 1. 读文档，抽三维

从源文档提取：

- **用户类型**（≤4 类）：映射到模板的四个固定色槽 `owner`(青) / `mate`(紫) / `frnd`(琥珀) / `team`(深青，通常留给"全体/系统"类)。只改 `USERS` 里的中文名，不新增色槽——色彩语义一致性比数量重要。
- **使用场景**：主流程 + 扩展场景，映射 `SCENS`（筛选标签）与 `ZONES`（画布分区）。分区一般 3–5 个，按叙事阶段划分而非机械按场景。
- **依赖端/系统**：每个节点的 `deps` 标签（车机/App/云端/硬件/账号系统……），全集控制在 5–9 个，命名全图统一。
- **节点** 8–16 个：`{id, z(分区), x, y, u(用户数组), scen(场景数组), deps, t(标题), s(一句话副标题), d(描述，尽量引用原文表述)}`。痛点节点加 `kind:"pain"`，边界/说明节点加 `kind:"note"`（可加 `wide:true`）。
- **边**：`{f, t, l?(标签), bend?:"left"}`。跨分区的关键跳转一定要有标签（如"无网时启用硬件"）；`bend:"left"` 用于会穿过其他节点的长回流边。

关键数字约束（上限、距离、容量）必须保留在节点文案里——这些是评审时最常被追问的。

### 2. 填模板

复制 `assets/template.html`，**只改**以下内容，其余一律不动：

| 位置 | 改什么 |
|---|---|
| `<title>`、`<h1>`、`.eyebrow`、`.stats` | 页面标题、来源文档日期、三维统计数 |
| 脚本顶部 `USERS` | 四个色槽的显示名 |
| `SCENS` | 场景 key → 显示名 |
| `ZONES` / `ZNAMES` | 分区定义与下拉选项名 |
| `ZMAP` | 旧存档迁移用的 id→分区映射（新项目可置 `{}`） |
| `KEY` | **必须改成项目唯一值**（如 `flow-<项目名>-v1`），否则不同项目的 localStorage 互相覆盖 |
| `DEFAULT` | 节点与边数据（第 1 步的产物） |
| 工具条筛选按钮的 `data-scen` / `data-user` 与文案 | 与 SCENS/USERS 对齐 |

初始坐标不必精确（分区框会自动贴合）：列 `x = 56 + 256*列号`；行参考 `y = 118 / 252 / 330 / 536`；目标是默认画布控制在约 1360×680 内，打开即一屏。

### 3. 校验（必做）

```bash
node scripts/validate.mjs <生成的.html>
```

脚本会真实渲染并断言：无 JS 报错、节点/边数量、单击节点弹出编辑表单、拖拽后连线跟随，并在同目录落一张截图。截图要亲眼看一遍：重点检查连线是否穿过节点（用 `bend` 或挪初始坐标解决）、分区标签是否被节点压住。

### 4. 交付

- 发布 Artifact（favicon 全程保持同一个 emoji，勿换）；同项目迭代时重发**同一文件路径**以保持链接不变
- 在 git 仓库内工作时提交产物
- 提醒用户：页面内的编辑存在各自浏览器本地；要把某人的版本设为所有人看到的默认，让 ta「导出 JSON」发回，把 JSON 并入 `DEFAULT` 后重新发布

## 换品牌配色

模板内置 NIOFlow（Ace）tokens。若用户给了别的品牌规范：只改 `:root`、`@media (prefers-color-scheme: dark)`、`[data-theme="dark"]`、`[data-theme="light"]` 四个块里的 CSS 变量值，组件样式一律通过 token 引用、不要直接改。主色只做强调（选中态/激活态/高亮连线），大面积仍用中性底——这是大多数品牌规范的共同要求。

## Mermaid 版（可选）

用户要"能贴进文档/GitHub/飞书"的版本时，另出一份 Mermaid markdown：flowchart（subgraph 对应分区，classDef 对应用户类型色）+ 交互类功能补一张 sequenceDiagram + 文末附可复制源码块。完整范例见 `references/mermaid-example.md`。Mermaid 语法务必先本地渲染验证再交付（npm i mermaid 后用无头浏览器跑一遍，语法错误会导致整图不显示）。
