# feature-animation · 功能教育动画

产出单个自包含 HTML（SVG + JS，零外部依赖）：自动循环播放的功能演示动画，可发 Artifact 链接、可直接嵌入车机 WebView / App。配合场景切换、分步字幕、日/夜双主题。

## 第 0 步：先对齐运动/交互逻辑，再写代码（最重要）

动手前用文字**复述功能的真实行为**让用户确认，宁可多问一轮：

- 物理约束是什么？（转角上限、速度、可动部件、方向）——真实产品动画画错物理会被一眼识破并返工。本仓库的教训：平移泊入第一版把车轮画成横转 90°，实际上限 40°、靠四轮同向打角斜向蹭移。
- 要**示意版**（夸张但概念清晰）还是**真实版**（严格遵守约束）？两者都要时分开出两版、两个链接，别混在一张图里。
- 用户给的参考链接打不开时（网络策略常拦截外站），直接索要截图/录屏/文字描述，不要凭想象猜参考内容。
- 用户教育的**核心差异点**是什么？（如"后轮也会转"）——它要单独成一个阶段并停顿强调，而不是一闪而过。

## 架构模式（参考 assets/example-zigzag-parking.html，含全部模式的可运行实现）

**舞台**：SVG `viewBox` 等比缩放 + 网格底 + 角落 HUD 角标（可放实时读数，如"转角 +20°"）+ 屏内功能按钮 pill——"点按开启"必须有视觉落点（按钮亮起 + 波纹），因为动画讲的就是"点这个按钮会发生什么"。

**时间轴**：`render(t)` 写成**时间的纯函数**（同一 t 永远渲染同一画面，不做增量状态累积）。好处：可循环、可从任意点续播、可用 `__seek(t)` 逐帧测试。结构：

- 由场景配置生成 segment 列表 `{type, dur, ...}`（idle → 点按 → 各动作阶段 → 回正 → 完成 → 停留，循环）
- 每段带累计起始时刻；render(t) 定位当前段并用缓动插值（easeInOutCubic 走位、easeOutBack 弹出）
- 阶段号写到 `data-phase`，CSS 据此驱动波纹、标注显隐——JS 管运动，CSS 管状态样式
- 关键数字（上限台数、距离、角度）放进字幕与 HUD，约束本身就是教育内容；动作幅度要服从场景约束（如邻车限位：空间大时大幅挪、夹缝中小幅碎挪），约束可见时价值才可见

**标配组件**：场景切换 chips（同一套动画、不同初始条件）· 分步字幕 + 步骤圆点 · 完成态绿色 check 弹出 · 待机轻呼吸避免死屏 · 双主题 tokens（组件只读 token）· `prefers-reduced-motion` 时静态显示终态。

**测试钩子约定**（必留）：`window.__seek(t)` 定点渲染、`__scn(id)` 切场景、`__play()` 恢复、`__info()` 返回 `{T, ...}` 时长元数据。

## 校验（必做）

```bash
node scripts/validate.mjs <生成的.html>
```

通用检查：无 JS 报错、按 T 的百分位逐相位截图、双主题、恢复播放后画面确实在推进。之后**按功能写专项断言**：终点位置是否精确、角度是否超上限、是否与障碍物（邻车等）重叠——用 `__seek` 全时间轴采样断言，别只看几帧。最后亲眼看截图：关键教育帧（打角、平移、完成）是否一眼能读懂。

## 交付

发布 Artifact（favicon 固定一个 emoji，迭代不换）；多版本并存时各占一个链接（示意版/真实版）；在 git 仓库内则提交，并附一段"动画节奏"说明（各阶段秒数、循环总时长）。
