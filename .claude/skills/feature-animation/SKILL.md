# feature-animation · 功能教育动画

产出两种形态，同一份源码：**交互 HTML**（自动循环、场景切换、分步字幕、日/夜双主题，零外部依赖）和 **MP4 视频**（`scripts/render-video.mjs` 一键导出，微信/飞书/手机可直接播）。

## 第 0 步：对齐需求，再写代码（最重要）

动手前用文字复述确认，宁可多问一轮。五件事：

1. **讲什么**——核心教育点是什么（如"后轮也会转""全程自动无需操作"）？它必须单独成阶段并停顿强调，不能一闪而过。
2. **真实行为与物理约束**——转角上限/方向/速度/触发条件。画错物理会被一眼识破并返工（本仓库教训：平移泊入曾把车轮画成横转 90°，实际是前轮上限 40°、后轮同向上限 8°，全程小幅斜挪碎步蹭移）。要**示意版**还是**真实版**？都要则两版两个链接。
3. **视角与主体**——车外俯视（位置/泊车类）· 车外侧视（充电/悬架/开门）· 座舱内部俯视（空调/座椅/车内感知）· 设备特写（换电站/充电桩/随车硬件/手机）· 车机或手机屏幕 UI（纯软件交互）· 或组合。**主体不是车也完全适用**——舞台、时间轴、字幕这套骨架与主体无关，换掉舞台里的图形即可。
4. **场景数量与初始条件**——同一套动画的不同起点（如"车位旁"vs"泊到一半"），用场景 chips 切换。
5. **交付形态**——交互链接 / MP4 视频 / GIF / **飞书文档（动画内嵌）** / 组合；视频需确认时长、比例、清晰度要求；飞书交付流程见 `references/feishu-doc-delivery.md`。

参考链接打不开时（网络策略常拦截外站），直接索要截图/录屏/文字描述，不要凭想象猜。

## 视觉资产

**配色**：默认 NIO 品牌规范，完整 tokens 见 `references/nio-colors.md`。主色 #00bebe/#00D4D4 只做强调（激活态/高亮/HUD 读数）；语义色独立（完成绿、警示琥珀、Negative 红极少用）；暗色 #0a0a0a 底。用户指定其他品牌时只换 token 值。

**车辆形象**（涉车演示必读）：
- **优先用官方图片**：用户提供官方渲染图/照片时，转 base64 以 `<image href="data:image/...">` 嵌入舞台底层，动画元素（光效/气流/轨迹/标注）作为 SVG 图层叠加其上。注意执行环境通常无法外网下载图片——需要真图时直接请用户上传，不要试图自己抓取。
- **没有真图时**：用 `assets/nio-vehicle.svg` 的统一「蔚来车」矢量（依据官方照片观察绘制，**不区分具体车型**），含三视图：`#nio-top` 顶视（SUV 比例 2.45:1、悬浮黑顶、瞭望塔激光雷达）/ `#nio-side` 侧视（分体灯组：细长 DRL 光带＋竖向主灯、翼子板气刃、贯穿尾灯、黑侧裙，内含 `#nio-welcome-mat` 迎宾光毯预留图层）/ `#nio-cabin` 座舱（2+2+2 六座、天空岛中轴、横向中控宽屏＋NOMI、椅背娱乐屏、氛围灯带、扬声器点位）。整组复制进舞台，CSS 变量（`--nv-body/--nv-roof/--nv-drl/…`）接主题 token 换色，默认值即官方照片色系（沙丘金＋黑顶＋米白舱）。造型依据与修正规则见 `references/nio-vehicle-design-notes.md`。不要自己从零画车。
- **非车辆主体**（人物、宠物、换电站、充电桩、手机、随车硬件等）：画与车辆资产同风格的简洁几何矢量——圆角矩形 + 圆为主、约 2px 描边、走同一套 token 色。人物用"圆头 + 胶囊身"，设备只画关键识别特征（换电站画站体+升降平台+电池块，手机画圆角屏+界面色块）。不追求写实，追求风格统一、一眼可辨。

## 架构模式（参考 assets/example-zigzag-parking.html，可运行）

**舞台**：SVG `viewBox` + 网格底 + 角落 HUD（实时读数：温度/转角/状态）+ 状态 pill——用户触发的功能给"点按开启"波纹；自动触发的功能给 AUTO 徽标自动亮起，"无需操作"本身就是教育点。

**时间轴**：`render(t)` 写成**时间的纯函数**（同一 t 同一画面，不做增量状态累积）——可循环、可任意定点、可逐帧测试。由场景配置生成 segment 列表（idle → 触发 → 动作阶段 → 完成 → 停留），render(t) 定位当前段用缓动插值（easeInOutCubic 走位 / easeOutBack 弹出）；阶段号写 `data-phase`，CSS 据此驱动状态样式——JS 管运动，CSS 管样式。关键数字（上限/距离/温度）放进字幕与 HUD；动作幅度服从场景约束（约束可见，价值才可见）。

**标配**：场景 chips · 分步字幕 + 步骤圆点 · 完成态绿 check（持续型功能用守护环替代）· 待机轻呼吸 · 双主题 tokens · `prefers-reduced-motion` 静态终态 · **测试钩子必留**：`__seek(t)` / `__scn(id)` / `__play()` / `__info()→{T,...}`。

## 动效词汇表（跨功能复用）

新功能先从这里挑选组合，再补功能特有的动效——避免每次从零发明，也避免只会照抄某个旧 demo：

| 类别 | 手法 | 已验证用例 |
|---|---|---|
| 位移 | segment 轨迹走位 + easeIO；规划虚线预告路径 | 泊车碎步、车主离车 |
| 感知/连接 | 元素脉冲环（扩散圆）、虚线连线 | 定位器检测、雷达、信号 |
| 空气/流体 | 流动 dash 线（stroke-dasharray 位移），换色表义 | 空调恒温（主色）、净化（绿） |
| 状态量 | HUD 数字随时间插值（tabular-nums） | 温度 27.5→24.0、转角 ±40° |
| 出现/消退 | 粒子逐个淡出（错峰 delay）、星光 pop、easeOutBack 弹出 | 异味消散、净化星光、落锁/勾 |

## 校验（必做）

```bash
node scripts/validate.mjs <生成的.html>
```

通用检查（无报错/逐相位截图/双主题/播放推进）之后，**按功能写专项断言**：终点位置、角度不超上限、不与障碍物重叠——用 `__seek` 全时间轴采样，别只看几帧。最后亲眼看关键教育帧截图：能不能一眼读懂。

## 视频导出

```bash
node scripts/render-video.mjs <file.html> --out demo.mp4 --scenes a,b [--gif]
```

原理：无头浏览器**实时录屏**（保证 CSS 动画与 JS 时间轴同步——不要用 `__seek` 逐帧截图拼视频，CSS 动画走墙钟会失步），再用 ffmpeg 裁切舞台区域、转 H.264（脚本自动从 npm 安装 `@ffmpeg-installer/ffmpeg`，二进制在包内无需外网）。默认 2 倍清晰度、每个场景完整一轮。

加 `--gif` 同时产出自动循环播放的 GIF（调色板两遍法，默认 720px/12fps，`--gif-width`/`--gif-fps` 可调）——GIF 以图片形式插入飞书文档/IM 会**自动播放**，是"动画直接展现在文档里"的载体。

## 交付

- 交互版发 Artifact（favicon 固定一个 emoji，迭代不换；多版本并存各占一个链接）
- 视频版直接发文件给用户（mp4 微信/飞书/iPhone 通用）
- **飞书文档**：环境已打通飞书工具时，按 `references/feishu-doc-delivery.md` 自动建文档——GIF 图片块开屏自动播放 + MP4 文件块高清收藏 + 交互链接备用；分步说明与关键参数从动画场景配置同步生成，完成后回发文档链接
- 仓库内则提交源码与视频，并附"动画节奏"说明（各阶段秒数、循环总时长）
